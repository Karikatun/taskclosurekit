# Контекст TaskProof

## Текущее состояние

В проекте есть локальный Python CLI для одного ограниченного цикла: контракт → baseline → фиксированная проверка staged whitespace → review оператора → закрытие. Доказательство привязано к снимку файлов, Git index и параметрам этого запуска. CLI хранит локальный подписанный журнал и при недоступном подтверждении блокирует переход.

Это узкая реализация, а не обещание полного минимального договора из [описания продукта](docs/PRODUCT_BRIEF.md). Допустимы режимы `Direct`, `Review` и `Investigation`; `TDD-first` пока явно отклоняется. Доступен только preset `git-index-whitespace-v1` с критерием `staged-whitespace`. Требование независимого review не может быть подтверждено текущим интерфейсом, поэтому при `independence: required` цикл остаётся заблокирован.

## Ограничения доказательств

Хеши и локальный HMAC помогают обнаружить случайное повреждение или несогласованные записи. Они не подтверждают качество кода, корректность критерия, личность автора, независимость review, добросовестность владельца машины или защиту от подмены локальной программы и ключа. Хранилище должно быть вне проверяемого репозитория; это не делает его доверенным для другой машины.

CLI отбрасывает сырой вывод проверочной команды и сохраняет ограниченные метаданные запуска. Команда фиксирована, имеет timeout и лимит вывода, а доступные POSIX resource limits применяются runner-ом. Лимит памяти присутствует только на Linux; macOS и прочие POSIX-среды не получают из этого среза эквивалентного лимита. Общая изоляция процесса и файловой системы не заявляется.

Проверен синтетический локальный fixture первого подключения. Он не читает и не меняет исходные проекты и не подтверждает интеграцию с `web-app-template`. Публикация, CI, installer, deployment и подключение к Codex остаются отдельными будущими работами.

## Следующий шаг

Перед расширением среза выбрать одно проверяемое расширение границ и отдельно определить требуемые доказательства. Не добавлять новые пресеты, действия, интеграции или installer по предположению. Сверять фактическое состояние и локальные инструкции перед каждой задачей; исходные проекты остаются справочными материалами.
