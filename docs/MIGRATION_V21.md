# Совместимость v2.1

Имя TaskClosureKit, namespace `python3 -m taskclosurekit` и task schema `taskclosurekit/v2` сохраняются. Contract по-прежнему выбирает preset IDs и не содержит shell/command. Builtin whitespace check доступен без project config. Для tests/typecheck/build требуется отдельная strict `taskclosurekit/presets/v1` configuration через `task create --preset-config`, расположенная вне repository/store. Не добавляйте command поля в task contract.

CREATE pin-ит config physical identity, definitions и authority dispatch inputs; authorize подтверждает их binding. Изменение config в текущей transaction не вводит новую authority: нужен новый task. Изменение программы/runner/runtime не гарантирует applicability старых evidence. Старые v2 journals не получают новые authority fields молча; неполный или несовместимый replay fail-closed, автоматическая миграция журналов отсутствует.

`human` в issuer/closure и `human_confirmed` в историческом trust vocabulary сохраняются как compatibility spelling. Семантический класс локальной authority — `operator_confirmed`, source `local-operator`, identity `unverified`, `identity_verified=false`. Это не verified human identity и не PROVEN independence. Старый `review --human` CLI flag сохранён; operator confirmation не меняет required independence при UNKNOWN.

Result envelope остаётся `taskclosurekit/result/v2`. Consumer читает structured operational status, decision, reasons, freshness и next action. Exit **4** теперь отделяет state STALE и причины `independence_unknown`/`unknown_state` от остальных policy blockers с exit **1**; **2** остаётся invalid input/state, **3** — operational failure, **0** — успешный неблокирующий результат. Consumer не должен считать любой успешно обработанный JSON допустимым claim или автоматически вызывать close.

Legacy `python3 -m taskproof`, schema-1 journals и stores остаются отдельным путём; их semantics не смешиваются с v2. Конвертация старых journals, PKI/OIDC, independence provider, network CI, installer, plugin framework и SDK не входят в v2.1. [Архитектура](ARCHITECTURE_V2.md) фиксирует сохраняемые primitives и узкий adapter seam.

Authorized preset без criterion остаётся допустимым в contract, но `check` теперь отклоняет его до journal mutation: `preset_has_no_criterion`, exit **2**. Consumers, которые запускали все разрешённые IDs подряд, выбирают только criterion-bound checks. Optional criterion позволяет явно запросить квитанцию проверки без обязательности для claim.

Dispatch validation теперь использует explicit supported grammar. Configurations с неоднозначными/unknown launcher flags, отсутствующими scripts/modules, site/global Python `-m`, mutable competing package path, bare Node loader package или неподдержанными shell/env/npx launchers отклоняются при CREATE. Existing local launch targets и package init/main/manifest требуют authority binding; runtime files — явного resource binding. Полный indirect dependency graph не выводится автоматически. Python `-I`/`-P` + `-m` также отклоняются. Named package `run` требует существующий string `scripts[name]`, script args идут только после `--`; `--cwd` разрешён только Bun. Supported argv нужно подготовить и подтвердить до новой transaction.

V2 process cleanup применяется на normal/timeout/output/error paths перед post-run capture. Эта поправка не вводит host sandbox или доказательство isolation от сменившего process group потомка. Task/result/preset schema fields остаются прежними.
